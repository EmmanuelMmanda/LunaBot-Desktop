Research & backtests

Set up a historical test, compare changes and read the results with the settings that produced them.

Start a backtest#

  1. Save a strategy first, then open Research → Add research.
  2. Select the intended strategy, market, timeframe and version.
  3. Choose Single replay for a first run.
  4. Enter Bars to replay (200–10,000) and Fixed test volume · lots.
  5. Review assumed spread, slippage, commission and the other displayed valuation settings.
  6. Select Run backtest.

Test volume and assumed costs describe the run. They do not change the account’s live trading rules or place orders.

Add research: choose the strategy, test method, bar count, volume and cost assumptions.

Open a run#

The list shows strategy, market, method, requested bars and status. Choose View details to read progress or a completed result. An active run can be cancelled using Cancel run.

Open Run configuration to see the settings saved with that run. If it fails, read the error before changing the strategy or starting another test.

Read the results#

Net P&L
The test’s profit or loss after its modelled costs.
Closed trades and win rate
How many trades completed and the share that ended with positive net results. A small trade count gives limited information.
Profit factor
Gross profit relative to gross loss. Read it alongside trade count and drawdown.
Equity curve and drawdown
How the modelled account value changed. Bar-close sampling can miss movements within a candle.
Requested, supplied and scored bars
Different counts can reflect available history and the candles needed to initialise indicators.

Read the assumptions and limits below the results. A qualification label refers to the app’s stated checks; it does not guarantee future results.

Change settings and compare#

A completed run keeps its saved configuration. To test a change, select Add research and create another run. To change the strategy itself, edit it in Strategies, save, then select the intended version for the next run.

Change one assumption at a time where possible. Compare the same market, timeframe, bar range and costs before drawing conclusions from a difference.

Other research methods#

Chronological
Separate earlier and later portions of the data using the configured windows.
Walk forward
Inspect successive training/test windows. Training prefixes are not automatically fitted or optimised.
Sensitivity
Compare declared parameter variants.
Cost stress
Compare declared spread, slippage or commission scenarios.

These methods expose Experiment options · JSON. Review the provided example and change only supported fields. Warmup must leave enough bars for the test; each child run needs at least 200 bars including warmup.

Review a trading problem#

In the Research review area, start a review of an account, strategy, Scout, proposal or order. LunaBot saves the available records, then Run checks compares them for inconsistencies.

“OK” means a particular record check passed. “Not enough data” means the saved records cannot answer that check. Creating a review does not start an AI session; use a connected assistant if you want further analysis.
